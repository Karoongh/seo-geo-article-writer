# Detailed Checklists & Templates

## Pre-Writing Research Checklist

- [ ] Primary search intent identified
- [ ] Secondary intents listed
- [ ] Real user questions extracted
- [ ] Funnel stage (awareness / consideration / decision / post-purchase)
- [ ] Persian search phrases and variants, plus Latin dashboard/error terms
- [ ] Key entities and related concepts mapped
- [ ] Competitor pages reviewed (title, H1, H2/H3, depth, gaps, CTA, FAQ, errors)
- [ ] The "information gain" decided: what will this page offer that top results do not?
- [ ] High-authority sources opened and recorded (title + URL)
- [ ] Business's real experience notes separated from general knowledge
- [ ] Related internal pages listed with natural anchor ideas
- [ ] Author/reviewer details requested (or marked `[TO CONFIRM]`)

## Mode B — Search Console Diagnosis Patterns

High impressions + low CTR → check:
- Title generic or mismatched with the query
- Meta description weak or lacking a value proposition
- H1 does not match dominant query language
- SERP features or AI Overview taking the click (check the live SERP)

Good position + low clicks → same as above, plus possible intent mismatch (informational vs transactional)

Many related queries with impressions but thin coverage → add sections for those exact questions

Position 8–20 with growing impressions → strengthen depth, direct answers, entities, internal links

(Full patterns: `correction-patterns.md`; method: `search-console-analysis.md`.)

## Writing Quality Checklist

- [ ] Introduction names the problem in the first 2–3 sentences
- [ ] Every important section starts with a short standalone answer
- [ ] No generic openings («امروزه…»، «در دنیای امروز…»، «در این مقاله قصد داریم…»)
- [ ] Varied sentence length, natural spoken-written mix
- [ ] Technical terms explained next to their first use
- [ ] No repeated paragraphs or filler
- [ ] No fabricated "we always see this in our workshop" unless real data was given
- [ ] Claims labeled by type (official / experience / probable / confirmed / user report)
- [ ] Safety warnings present where risk exists
- [ ] Tables used only when they speed understanding
- [ ] FAQ answers are independent and not H2 copies
- [ ] Persian typography: ی/ک, ZWNJ, digits consistent (linter clean)

## Structure Template (Problem / Fault / Service articles)

H1: Clear problem or service name + model/context if needed

H2: What this problem/error means
H2: Common symptoms
H2: Probable causes (with confidence level when possible)
H2: How to diagnose / what to check
H2: Repair or solution options
H2: When you must stop and go to a specialist
H2: Cost factors (no invented numbers)
H2: Related services / internal links
H2: FAQ (only if it adds value)

Adapt for other intents:
- **Informational:** what it is → how it works → types/variants → when it matters → common mistakes → next steps
- **Comparison:** quick verdict (who should pick what) → criteria → table → each option's strengths/limits → recommendation by situation
- **How-to:** goal and prerequisites → numbered steps with checks → common failures → when to stop → what to do next
- **Service/local page:** what the service is → who needs it → process → what affects price/time → proof (real work, real data) → how to book

## Multi-Role Review Questions

**User:** Did I get a clear answer on the first screen?
**Expert:** Any wrong or dangerously simplified technical claim?
**SEO:** Is every high-value query covered with proper heading, entities, and links?
**AI engine:** Can I extract a clean 1–3 sentence answer from each major section without extra context?

## Final Delivery Checklist

- [ ] One H1 only
- [ ] Logical H2/H3 hierarchy
- [ ] Search intent fully covered
- [ ] Direct answers present
- [ ] No keyword stuffing (linter reviewed)
- [ ] Semantic entities covered naturally
- [ ] Information gain present (something competitors lack)
- [ ] Useful internal links
- [ ] Credible external sources, each actually opened
- [ ] Natural CTA
- [ ] Correct contact/address if local (only as supplied)
- [ ] Strong SEO title + meta description
- [ ] Clean, stable slug
- [ ] Schema recommendation per `schema-guide.md` (no FAQ/HowTo rich-result promises)
- [ ] Real FAQ or none
- [ ] Natural image ALTs; AI images not presented as real photos
- [ ] Author/reviewer/AI-disclosure decisions made explicit
- [ ] Mobile-readable paragraphs
- [ ] No unsubstantiated claims or invented numbers
- [ ] No competitor copying
- [ ] Actually useful for a real person
